Committed convention: SPREAD = sum v_j*(p_j - S_j) direct, INV = PnL - spread residual,
PnL = cash_T + q_T*S_final. v_j = sgn*size, sgn=+1 when the MM sold.
8 seeds x 604800s (7.00 days), MM present, k=0.17763 C=13.66 gamma=1.3392e-06.
lam=1.8040 p_market=0.0126 disp=0.0055, JOIN clipping. Arms this run: life=720, life=60

With INV as a residual, INV verifies nothing; every error in the
computation lands there by construction.

Gate 2 and Gate 3 are both near-tautological. Gate 2 holds because
cash is benchmark-independent; Gate 3 holds because p cancels:
SPREAD(V) - SPREAD(lag) = sum sgn*sz*(S_lag - V) identically, so it
passes unless a field name is mistyped. Neither is evidence the legs

    Is spread(lag)/BTC just the maker's own half-spread h?
    No; and an earlier version of this file said it should be.
    That two-term identity was wrong and is withdrawn:
        Wrong:    SPREAD(X)/BTC = h - E[d_X]
    The maker quotes around its reservation price r = S - q*C,
    not around S, so the per-fill edge carries a third term:
        edge = sgn*(p - S) = h - q*C*sgn
        SPREAD(lag)/BTC = h - C*E[q*sgn]
    The h gap is therefore NOT error. It is the realised
    inventory-skew cost; the one term this project is about.
    h is read from the maker's private quote log, not inferred:
